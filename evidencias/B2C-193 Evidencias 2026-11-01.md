- User type: Logueado
- Viewport: Desktop 1440x900
- Ubicacion: Checkout (Mi Pago)
- Sesión iniciada con la cuenta {USER_AUTH_001}
- El carro contiene {SKU_VALID_001} x {UNIDADES_SOBRE_MINIMO} y el subtotal es mayor o igual a {MONTO_MINIMO_COMPRA}
- Despacho a domicilio configurado con {DIRECCION_DESPACHO_001} y una ventana de entrega seleccionada
- DevTools abierto con bloqueo de la request {CHECKOUT_API_ENDPOINT} (Network request blocking)

**Data utilizada**

- {BASE_URL} = https://smu-dev-development.sfdc-8tgtt5-ecom1.exp-delivery.com/

- {CHECKOUT_API_ENDPOINT} = TBD
- {SKU_VALID_001} = 000000000000675191-UN
- {UNIDADES_SOBRE_MINIMO} = 11
- {MONTO_MINIMO_COMPRA} = 20000
- {DIRECCION_DESPACHO_001} = Casa
- {USER_AUTH_001} = girolamo_coppo@hotmail.com

**Pasos ejecutados**

1. El usuario ingresa a {CART_URL}.
2. El sistema carga el carrito.
3. El usuario hace clic en "Continuar con la entrega" y luego "Continuar" en el modal de sugeridos si aparece.
4. El sistema carga la página "Datos de entrega" (Mis Envíos).
5. El usuario hace clic en "Ir a pagar".

**Resultado esperado**

Se muestra la pantalla de error con los botones "Reintentar" e "Ir al inicio" y no se muestra contenido del Checkout (productos, totalizer, medios de pago ni botón "Pagar y finalizar").

**Resultado obtenido**

Verificado 2026-11-01 (Desktop/Mobile, Chromium): Causa: {CHECKOUT_API_ENDPOINT} (…/shopper-orders/v1/…/orders) no corresponde a ninguna request que haga el Checkout al cargar: al bloquearla, «Ir a pagar» abre «Mi Pago» con normalidad (las requests de carga son baskets, payments-cards/cards y smu-checkout/payment-availability). Como referencia, bloqueando la de tarjetas (cards) aparece un error parcial «Ocurrió un error al cargar tus medios de pago» con «Reintentar» e «Ir al inicio» solo en esa sección, y el resto del Checkout sigue visible; no es la pantalla de error completa que describe el TC. Acción: declarar en {CHECKOUT_API_ENDPOINT} la request cuyo fallo provoca la pantalla de error completa del Checkout.

**Observación**

Verificado 2026-11-01 (Desktop/Mobile, Chromium): Causa: {CHECKOUT_API_ENDPOINT} (…/shopper-orders/v1/…/orders) no corresponde a ninguna request que haga el Checkout al cargar: al bloquearla, «Ir a pagar» abre «Mi Pago» con normalidad (las requests de carga son baskets, payments-cards/cards y smu-checkout/payment-availability). Como referencia, bloqueando la de tarjetas (cards) aparece un error parcial «Ocurrió un error al cargar tus medios de pago» con «Reintentar» e «Ir al inicio» solo en esa sección, y el resto del Checkout sigue visible; no es la pantalla de error completa que describe el TC. Acción: declarar en {CHECKOUT_API_ENDPOINT} la request cuyo fallo provoca la pantalla de error completa del Checkout.
